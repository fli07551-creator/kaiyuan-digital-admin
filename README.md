4. **真实菜单树**：从主框架 HTML 的 `menuOne`（一级）/ `menuTwo`（二级）属性解析出完整菜单：

## 八、部署到 Render

### 8.1 仓库中已就绪的部署配置

| 文件 | 作用 |
| --- | --- |
| `render.yaml` | Render 蓝图（Blueprint），一键创建 Web Service |
| `package-lock.json` | 锁定依赖版本，保证云端构建可复现 |
| `.gitignore` | 排除 `node_modules` / `.next`，避免推送构建产物 |
| `package.json` → `start` | 改为 `next start`，Render 注入的 `PORT` 会被 Next.js 自动读取 |

> 本地预览仍用固定端口：`npm run start:local`（3001），`npm run dev`（3001）。

### 8.2 方式 A：Blueprint 一键部署（推荐）

1. 把本项目推到 GitHub（见 8.4）。
2. 打开 Render Dashboard → 右上 **New +** → **Blueprint**。
3. 选择刚推送的仓库 → **Connect**。
4. Render 自动读取 `render.yaml`，列出待创建服务 `kaiyuan-digital-admin`（free / singapore）→ **Apply**。
5. 等待构建完成，访问 `https://kaiyuan-digital-admin.onrender.com`。

### 8.3 方式 B：手动 Create a new Web Service（对应你截图那页）

表单逐项填写：

| 字段 | 填写值 |
| --- | --- |
| Name | `kaiyuan-digital-admin` |
| Project（可选） | 留空或新建 |
| Language | `Node` |
| Branch | `main` |
| Region | `Singapore`（离国内最近） |
| Root Directory | **留空**（仓库根目录就是项目根目录） |
| Build Command | `npm install --include=dev --no-audit --no-fund && npm run build` |
| Start Command | `npm start` |
| Instance Type | `Free` |

**Environment Variables**（点 Advanced 或部署后到 Environment 页添加）：

```
NEXT_TELEMETRY_DISABLED = 1
```

> 不要自己设置 `PORT`，Render 会自动注入并通过它决定监听端口。
> **也不要设置 `NODE_ENV=production`**：Render 构建阶段会带入环境变量，而该变量会让 `npm install` 跳过 devDependencies，导致 `tsconfig.json` 的 `@/*` 别名失效，构建报 `Module not found: Can't resolve '@/lib/...'`。构建命令里的 `--include=dev` 就是为此兜底的。

### 8.4 推送到 GitHub

```bash
cd 企业管理复刻
git remote add origin https://github.com/<你的GitHub账号>/kaiyuan-digital-admin.git
git branch -M main
git push -u origin main
```

仓库需为 **Public**（Render 免费版拉取公开仓库最省事；私有仓库则需要授权 Render 访问）。

### 8.5 免费实例注意事项

- **冷启动**：Free 实例闲置约 15 分钟后休眠，再次访问需 30–60 秒唤醒。
- **内存 512MB**：Next.js 构建阶段较吃内存，构建耗时约 3–5 分钟；若构建 OOM，升级到 Starter（$7/月）即可。
- **自动部署**：`render.yaml` 中已设 `autoDeploy: true`，之后 `git push` 到 `main` 会自动重新部署。
- **自定义域名**：Settings → Custom Domains 绑定后按提示配置 CNAME。


### 8.6 已知构建失败与处理

**现象**：部署状态 `Failed deploy`，日志中出现
`Module not found: Can't resolve '@/lib/dashboard'`、`'@/components/AppShell'`。

**原因**：`npm install` 只装了生产依赖（日志里是 `added 23 packages`，正常应在 100 以上）。
devDependencies 缺失后，Next.js 不加载 `tsconfig.json` 的 `paths` 别名，`@/*` 全部解析失败。

**触发条件**：在 Render 环境变量里设置了 `NODE_ENV=production`（构建阶段即生效），
或使用了 `npm ci --omit=dev` / `--production`。

**修复**：`render.yaml` 中已做两处调整——
1. 移除 `NODE_ENV` 环境变量；
2. 构建命令改为 `npm install --include=dev --no-audit --no-fund && npm run build`。

改完推送到 `main`，在 Render 的 Blueprint 页面点 **Manual sync** 重新部署即可。

## 九、权限管理（角色 / 菜单权限）

### 9.1 能力

- **5 个预设角色**：系统管理员（全权限，锁定）、销售经理、生产主管、财务主管、人事行政
- **两级授权粒度**：一级模块（整块开关，支持半选态）+ 二级功能项（逐项勾选）
- **菜单联动**：切换身份后侧栏立即按权限过滤，无权限的模块与功能不出现
- **越权拦截**：直接输入 URL 访问无权限的功能页，显示「无访问权限」引导页
- **持久化**：授权配置与当前身份存 `localStorage`（键 `kaiyuan-rbac-v1`），刷新不丢
- **恢复默认**：每个角色可一键回到预设授权

### 9.2 使用方式

1. 右上角头像旁的**下拉框**切换当前登录身份（演示用）
2. 点顶栏盾牌图标，或走侧栏「应用中心 › 权限控制」
3. 在权限矩阵里勾选/取消，改动即时生效
4. 切到对应角色，观察侧栏变化；再用地址栏直接访问越权页面验证拦截

### 9.3 代码位置

| 文件 | 职责 |
| --- | --- |
| `src/lib/rbac.ts` | 角色定义、预设授权规则、功能键生成 |
| `src/components/RbacProvider.tsx` | 权限上下文：当前身份、授权表、`has()` 判定、可见菜单 |
| `src/components/PermissionGuard.tsx` | 功能页越权拦截 |
| `src/app/system/permissions/page.tsx` | 权限矩阵配置页 |

> 说明：当前为**前端演示级**权限（数据存浏览器本地）。生产环境需改为后端签发 Token + 接口级鉴权，
> 菜单权限只是第一层，接口必须独立校验，否则可被绕过。

### 9.4 构建策略调整

二级功能页由「89 页全部静态预渲染」改为**按需服务端渲染**（`/m/[module]/[page]` 为 Dynamic），
构建产物从 94 个页面降到 6 个，显著降低 Render 免费实例（512MB）的构建内存压力，页面响应无明显差异。

### 10.2 列结构按模块族自动适配

- **报表类**（各类报表、统计、成本、MRP 运算…）→ 统计项目 / 本期 / 上期 / 环比 / 占比
- **设置类**（各类设置、参数…）→ 参数名称 / 参数值 / 作用说明 / 更新时间 / 状态

接入真实数据时，只需把 `getListSchema()` 的 `rows` 换成接口返回即可，列定义与交互无需改动。

## 十二、登录与身份

### 12.1 登录机制

- 入口 `/login`：左侧品牌区 + 右侧登录卡片，支持密码显隐、记住账号
- 校验规则：账号支持**用户名或用户编号**；密码默认 `123456`（用户表 `password` 字段可改）
- 拦截条件：账号不存在、密码错误、账号已停用（`停用` 状态禁止登录）
- 登录态存 `localStorage`（键 `kaiyuan-auth-v1`），刷新保持；顶栏右侧可**退出登录**
- 未登录访问任何后台页面会被重定向到 `/login`；登录页不套用后台框架

### 12.2 初始系统管理员

系统只预置一个管理员账号，登录页不再展示任何演示账号或一键填入入口。

| 账号 | 岗位 | 对应权限角色 | 可见一级模块 | 初始密码 |
| --- | --- | --- | --- | --- |
| 吴志兵 | 超级管理员 | 系统管理员 | 全部 15 个 | 123456 |

其他账号全部由管理员登录后在「应用中心 → 用户管理」中新增、编辑、导入或重置密码。
系统管理员账号受保护，不能删除或停用，避免误操作导致无人可登录。

### 12.3 登录身份驱动权限

登录成功后，`RbacProvider` 会按用户表里的 `role` 文本调用 `roleIdFromText()` 映射到权限角色，
侧栏与功能页权限随之生效。因此**不再需要手动切换角色**——换账号登录即是换权限视角。

`roleIdFromText` 映射规则：超级管理员/电商管理员→admin；销售/采购→sales；财务/会计→finance；
人事/人力/行政→hr；生产/库管/质检/设备/研发/工艺→production。

### 12.4 密码管理

用户管理页新增/编辑表单里有「登录密码」字段（新增默认 123456）；行内钥匙图标可单独**重置密码**（至少 6 位），
重置后该用户即刻用新密码登录。改密码后需重新登录验证。

## 十三、账号数据迁移与管理员保障

### 13.1 变更内容

- 内置种子用户由 12 个账号缩减为**仅系统管理员吴志兵**；
- 登录页移除演示账号列表、一键填入和「恢复演示账号」按钮；
- 用户表存储键从 `kaiyuan-users-v1` 升级为 `kaiyuan-users-v2`；
- 首次加载旧数据时，自动清除 11 个旧演示账号，只保留管理员以及管理员自行新增的账号；
- 系统管理员账号禁止删除和停用；密码可在「用户管理」中重置。

### 13.2 迁移规则

`loadUsers()`（auth.ts）读取新键；若无新数据，则读取旧键并按用户编号过滤旧演示账号，
把保留下来的自建账号与管理员合并后写入新键，并删除旧键。
因此升级后不会再次出现 ceshi、杜晓晓等演示账号。

### 13.3 应急办法

如果管理员密码被改错且无法登录，可在浏览器控制台清除站点数据后刷新，
或在无痕/隐私窗口打开站点，系统会重新初始化默认管理员账号（吴志兵 / 123456）。

## 十四、权限编辑与登录身份解耦（管理员权限丢失修复）

### 14.1 现象

用管理员账号（吴志兵）登录后，进「权限控制」页点了某个角色标签（如"销售经理"），
顶栏角色就变成"销售经理"、侧栏菜单从 16 项缩到 6 项——管理员权限"消失"了，
返回首页也不恢复。

### 14.2 原因

权限页的角色标签复用了 `setRoleId()`（当前登录身份的角色状态），
导致"选择要编辑哪个角色"误改了"当前登录者是谁"。

### 14.3 修复

- `RbacProvider` 新增独立的 `editRoleId`（正在编辑的角色）状态，与登录身份 `roleId` 分离：
  - `roleId` / `has()` / `visibleMenu`：始终由登录身份决定，权限页无法改动。
  - `editRoleId` / `editRole` / `hasFor()`：仅供权限页勾选与编辑使用。
  - 权限页切换标签只调用 `setEditRoleId()`，勾选/恢复默认操作都带上 `editRoleId` 目标。
- 登录时把两个状态都重置为登录身份对应角色，避免残留上次选中的编辑对象。
- 持久化同时保存 `editRoleId`，刷新后编辑对象不丢，但不影响登录身份。

### 14.4 验证

Edge 无头浏览器端到端：吴志兵登录 → 权限页点"销售经理" → 顶栏仍"系统管理员"、
侧栏仍 16 项，权限页统计切到销售经理的 16/90 项 → 返回首页角色与菜单保持不变。通过。
